Welcome to Arvlo!

Arvlo is a modern documentation platform designed to help teams create, organize, and publish beautiful documentation with ease. Whether you're documenting a product, API, SDK, or internal knowledge base, Arvlo provides the tools you need to keep your documentation organized and up to date.

This guide introduces the core concepts of Arvlo and helps you understand how documentation is structured before you create your first project.

## What is Arvlo?
Arvlo is a documentation platform built for developers, teams, and businesses.

With Arvlo, you can:

- Create structured documentation.
- Publish documentation to a public website.
- Organize pages with categories and nested navigation.
- Create release notes and changelogs.
- Collaborate with teammates.
- Track analytics and user engagement.
- Enhance documentation with interactive components.

Everything is designed around making documentation easy to write, maintain, and navigate.

## Why Use Arvlo?
Documentation is often the first experience users have with your product. Clear, well-organized documentation helps users find answers faster and reduces the time spent answering repetitive questions.

Arvlo helps you:

- Keep documentation organized as it grows.
- Publish updates quickly.
- Create consistent documentation across your team.
- Improve the reader experience with interactive components.
- Scale from small projects to large documentation sites.

Whether you're launching a new product or maintaining an established platform, Arvlo grows with your documentation.

## Core Concepts
Before you begin, it's helpful to understand a few core concepts.

### Projects
A project contains all of your documentation, releases, settings, and collaborators.

Most users create one project for each product or service they maintain.

### Documentation Pages
Documentation is organized into individual pages written in Markdown.

Pages can be grouped into categories, nested beneath other pages, and organized however you like.

### Categories
Categories divide your documentation into logical sections such as:

- Getting Started
- Guides
- API Reference
- Releases

### Drafts
Documentation begins as a draft and can be reviewed before publishing.

Drafts are only visible to project members until they're published.

### Publishing
Publishing makes your documentation publicly available.

You can continue editing published pages and publish updates whenever you're ready.

## Documentation Structure
A typical documentation site might look like this:

```text
Getting Started
├── Welcome
├── Create Your First Project
└── Project Dashboard

Writing Documentation
├── Creating Documentation
├── Organizing Documentation
├── Markdown Guide
└── Custom Components

Releases
├── Creating Releases
└── Release Notes
```

As your documentation grows, you can add additional categories, nested pages, integrations, API references, and more.
