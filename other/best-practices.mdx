# Best Practices

## Design for reader outcomes

Give each page one clear purpose. Start with the result the reader wants, provide the smallest complete workflow, and link to the next likely task.

## Keep navigation shallow

Use products for distinct documentation sets and sections for broad topics. Prefer short page titles and a predictable order: overview, setup, common workflows, advanced material, then troubleshooting.

## Work in drafts

For browser-edited projects, save incomplete changes as drafts and use the rendered preview before publishing. Repository projects should use the normal Git review process and then sync.

## Maintain trust

Set a documentation owner, enable review reminders, and mark pages reviewed after verifying them. Watch the documentation health report for stale pages, broken links, thin content, answer gaps, and release drift.

## Learn from readers

Review searches, feedback, and suggestions in **Reader insights**. Move answer gaps through open, planned, and resolved states so the queue reflects real work.

## Preserve links

When a slug changes, review the suggested redirect. Test internal links after reorganizing navigation and before announcing a release.
