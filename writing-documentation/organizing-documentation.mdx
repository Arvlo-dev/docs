# Organizing Documentation

Arvlo uses products, sections, and pages.

```text
API
├── Getting started
│   ├── Overview
│   └── Authentication
└── Reference
    ├── Errors
    └── Endpoints
```

Use a product for a distinct documentation set, a section for a broad topic, and a page for one focused reader task.

## Nested pages

This has not yet been implemented.

## Organize in the dashboard

Choose **Project tools → Navigation & appearance**. Browser-edited projects can create and rename products and sections, move pages between them, reorder pages and sections, publish or hide pages, and assign icons.

Repository projects derive their initial structure from file paths and frontmatter. You can still reorder pages, assign icons, and hide files in Arvlo, but source paths remain managed in Git.

## Reader selectors

Project owners can define up to ten selectors, such as Version, Framework, or Audience, in project settings. Each selector can have up to twelve choices.

Use `readerContexts` frontmatter to limit a whole page to choices. Use the `Variant` custom component when only part of a page varies. The published navigation and search results respond to the reader's active choices.

## Keep the structure useful

- Put setup content before advanced workflows.
- Keep section names short and stable.
- Use descriptive page titles.
- Hide obsolete repository files until they can be removed at the source.
- Add redirects when a public path changes.
