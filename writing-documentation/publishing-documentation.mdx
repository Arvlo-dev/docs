# Publishing Documentation

## Browser-edited projects

**Save draft** stores the current editor state without changing the live page. If a published version already exists, readers continue to see it. **Discard draft** removes the private changes. **Publish** makes the editor state live and stores the previous published version in revision history.

The rendered preview updates as you edit. It is the place to check Markdown, MDX components, links, reading layout, and metadata before publishing.

## Repository projects

The repository is the source of truth. Commit changes to the configured branch, then choose **Refresh from Git** or let a configured provider webhook mark the project for synchronization. Arvlo publishes synchronized files unless they are hidden in navigation.

## Hide a page

Open **Project tools → Navigation & appearance**, clear **Published** for the page, and save navigation. Hiding removes the page from the public site without deleting its content.

### Page-editor unpublish action

This has not yet been implemented.

## Redirect moved pages

When publishing a browser page changes its public path, Arvlo can suggest a redirect from the previous path. Review it under **Project tools → Redirects** so existing bookmarks and links continue to work.

## Delete content

Browser-edited pages can be permanently deleted from **Project tools**. Repository pages must be deleted in Git or hidden from navigation. Deleting a project removes its project record, pages, revisions, and snippets.
