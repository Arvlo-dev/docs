# Creating Documentation

## Browser-edited pages

Open a browser-edited project and choose the **+** beside **Pages**. Enter the page fields and write MDX in the editor. The preview uses the same renderer as the published site.

Page fields include title, URL slug, description, product, section, content width, on-this-page navigation position, hero image URL, and reading metadata visibility.

Choose **Save draft** to keep changes private or **Publish** to make them live. New draft-only pages remain hidden until their first publish.

## Repository pages

For GitHub and GitLab projects, create or edit `.md` and `.mdx` files in the configured branch and docs folder. Choose **Refresh from Git**, or use a configured webhook, to synchronize. Repository content is read-only in the Arvlo dashboard.

## Frontmatter

Frontmatter is supported for both repository and browser-edited pages.

```yaml
---
title: Authentication
description: Authenticate requests to the API.
release: v2.4.0
owner: Developer Experience
reviewedBy: Quinn
reviewedAt: 2026-10-21
supportedVersions:
  - v2
readerContexts:
  framework:
    - React
---
```

`title` and `description` populate page metadata. The remaining fields contribute review, release, compatibility, and reader-selector information. Browser page layout is configured in the editor rather than frontmatter.

## Writing content

Arvlo supports GitHub-flavored Markdown, syntax-highlighted code fences, Mermaid diagrams, and its documented custom MDX components. Use a single `#` heading for page health checks even though the page title is also rendered by the site shell.

## Revision history

Publishing a change to an existing browser-edited page stores the prior published version. Open **Project tools → Revision history** to compare or restore it. Repository projects use Git history instead.
